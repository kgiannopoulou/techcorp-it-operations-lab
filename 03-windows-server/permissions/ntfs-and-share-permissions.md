## 1. How Windows decides

| Concept | Rule | TechCorp choice |
|---|---|---|
| Share vs NTFS | Over the network the **more restrictive** of the two wins | Share = Authenticated Users *Change*, so NTFS alone decides |
| NTFS grants add up | A user's access = union of every Allow entry for the user and all their groups | Access is granted only to `DL_FS_` groups (AGDLP) |
| Deny beats Allow | An explicit Deny overrides any Allow | **No Deny entries anywhere** – they make access impossible to reason about; we simply don't grant |
| Inheritance | Entries flow from parent to child unless the child *disables inheritance* | Broken only on `Finance\Payroll` |
| Traverse | *Bypass traverse checking* (granted to Everyone by default) lets a user open a deeper path even without access to the folders above | Used deliberately for `HR\Payroll-Inputs` (P: drive) |
| ABE | Access-based enumeration hides folders a user cannot read | On for every data share |
| Owner | The creator of a file is its owner and can always change its permissions | Accepted; Modify (not Full Control) means users can't change permissions on folders they don't own |

## 2. Access levels used

`Deploy-TechCorpFileShare.ps1` turns the three levels in the CSV into these
NTFS entries:

| Level | Entry 1 | Entry 2 | Result |
|---|---|---|---|
| **RW** | *Modify* – **subfolders and files only** | *Read & execute + Create files + Create folders + Write attributes* – **this folder only** | Full day-to-day work inside the folder, but the folder itself cannot be deleted or renamed – a classic "where did the Finance folder go?" incident avoided |
| **RO** | *Read & execute* – this folder, subfolders and files | – | Open and copy, no changes |
| **List** | *Read & execute* – **this folder only** | – | See the folder's contents (with ABE: only what you may open), nothing below |

Every folder also has `Administrators` and `SYSTEM` *Full control* (inherited
from `D:\Shares`, re-added explicitly where inheritance is broken).

## 5. Requesting a change

1. Ticket from the **data owner** (department manager) – not from the user.
2. Prefer group membership: add the person to the existing `GG_` group (`ad-groups.csv`).
3. New access pattern: add a row to `file-permissions.csv` (+ a `DL_FS_` group, + an expectation in `access-tests.csv`). CI shows the new matrix.
4. Run `Deploy-TechCorpAd.ps1`, then `Deploy-TechCorpFileShare.ps1`.
5. Git history is the audit trail of *who approved what, when*.

## 6. Verifying effective access in the lab

- *Folder → Properties → Security → Advanced → Effective Access → Select a user* (e.g. `nile.dok` on `Finance\Payroll` → nothing ticked).
- PowerShell on TC-FS01: `(Get-Acl D:\Shares\Departments\Finance\Payroll).Access | Format-Table IdentityReference, FileSystemRights, IsInherited`.
- `Test-TechCorpAd.ps1 -FileServer TC-FS01` compares every folder's explicit entries and inheritance flag with the plan.
